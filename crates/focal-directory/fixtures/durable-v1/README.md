# Original native directory placement V1 corpus

These files were produced by the original live Postcard/Serde implementations,
before the frozen directory codecs or `placement_digest` routing changes. They
are compatibility inputs, not expected values generated by the new codecs.
The initial capture contains 44 data files. Five additional field-order sentinels
were subsequently generated by the retained original library; that run reproduced
all initial files byte for byte before the additional files were installed.

`capture.json` records the exact compiler, commands, source identities, linked
library and generator executable SHA-256 identities, original placement hashes,
and every data file's byte count and SHA-256. Build paths are mutable locations;
the recorded content hashes identify the actual artifacts. `source-files.json`
and `source-snapshot/` preserve every pre-codec directory source file plus the
model's serialized ID/counter leaves. The old writer library was compiled from
those directory sources, using the specifically recorded release dependencies.
`generator.rs.txt` is the exact standalone capture program. It is a test utility
and contains assertions and cloning that are forbidden in production code.

## Stored values

Every `.rows` file is an original Postcard `Vec<T>` without an outer magic.

| File stem | Original element type | Rows |
|---|---|---:|
| `cluster-ids`, `region-ids`, `zone-ids`, `partition-ids`, `log-group-ids`, `operation-ids`, `work-ids` | Corresponding native ID | 4 each |
| `namespace-keys` | `NamespaceKey` | 3 |
| `namespace-ranges` | `NamespaceRange` | 4 |
| `node-enrollments` | `NodeEnrollment` | 3 |
| `node-loads` | `NodeLoad` | 3 |
| `node-records` | `NodeRecord` | 6 |
| `failure-classes` | `FailureClass` | 3 |
| `durability-intents` | `DurabilityIntent` | 9 |
| `placement-policies` | `PlacementPolicy` | 18 |
| `placements` | `Placement` | 3 |
| `placement-specs` | `PlacementSpec` | 18 |
| `placement-digests` | `ContentHash` returned by original `placement_digest` | 18 |
| `session-fence-kinds` | `SessionFenceKind` | 3 |
| `session-fences` | `SessionFence` | 9 |
| `replica-ready` | `ReplicaReady` | 3 |
| `delegation-fences` | `DelegationFence` | 4 |

`placement-00.bin` through `placement-17.bin` are individual original
`PlacementSpec` values corresponding to the vector and digest rows. Their hash
preimage is exactly `b"focal:placement:v1\0"` followed by the original serialized
specification; the zero byte is part of the domain separator. The original
one-mebibyte encoded-size preflight is tested separately without adding a large
fixture file.

The five `distinct-*.bin` files contain individual `NodeLoad`, `NodeEnrollment`,
`SessionFence`, `ReplicaReady` and `DelegationFence` values. They use different
sentinels for every same-typed field to detect field swaps that uniform extreme
values cannot detect.

The corpus includes every failure-class and session-fence-kind ordinal; empty,
populated and 130-entry maps; region ordering; absent/present node load and range
end; zero/high-bit/maximum IDs; zero/maximum counters; non-ASCII endpoints; and
zero/one/maximum failure budgets. Some cases are intentionally invalid under
placement or enrollment admission: reversed/empty namespace ranges, unknown
regions, empty voter sets, contradictory member incarnations, zero fence
coordinates and equal route epochs. Decoding preserves those stored values
without silently revalidating or repairing them.

## Collection decoder probes

`unsorted-duplicate-placement.input` and `unsorted-duplicate-policy.input` are
explicitly crafted map/set byte sequences, not claimed output of a canonical
map/set writer. Their `.normalized` companions were produced by the original
live decoder followed by the original live writer. They pin ordered iteration,
set deduplication, and the original map rule that the last duplicate value wins.
The new collection decoders must preserve those rules while ignoring untrusted
size hints for eager allocation.

## Reproducing and checking

1. Restore `source-snapshot/*.rs.txt` under a temporary source directory, removing
   only the trailing `.txt`; retain the module names and layout. The `model-`
   snapshots document dependency leaf shapes rather than directory modules.
2. Follow `capture.json`'s `library_compile` arguments, replacing the input
   `lib.rs` and output paths with the temporary paths. Use the recorded linked
   dependency identities when reproducing the exact original build. Building
   replacement dependencies requires separately checking their serialized leaf
   contracts; a same-named rlib does not prove byte identity.
3. Compile the preserved generator using `generator_compile`, linking the
   original-writer library from step 2. Run it into a new empty directory. The
   generator refuses to overwrite previously captured files.
4. Compare all 49 generated data files against `capture.json` and the checked-in
   bytes. The five sentinel additions were captured with this temporary-output
   comparison procedure, including byte equality for the initial 44 files.

This corpus does not freeze the directory authority/control/partition command
and checkpoint graphs, their signatures, or the outer Session envelope. Those
contracts require their own explicit representations and integration checks.

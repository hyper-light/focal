# Performance — allocation admission (2026-09-12, macOS arm64)

Host: Apple Silicon (arm64), 18 logical CPUs, macOS. Build: `bench` profile
(optimized). Bench: `cargo bench -p focal-memory --bench budget` (dependency-free
`harness = false` binary; iteration count overridable via `FOCAL_BENCH_ITERS`).

`focal_memory::MemoryBudget` is the admission path every operation charges through
before it does any work, so its cost bounds the whole system's per-operation
floor. These are microbenchmarks of that path, not end-to-end throughput.

| Case | ns/op | ops/s |
|---|---|---|
| reserve + commit + drop (uncontended) | 7.7 | 130 M |
| reserve + drop, uncommitted (refusal path) | 7.6 | 131 M |
| child budget create + nested reserve/commit | 26.8 | 37 M |
| reserve/commit, 2 threads sharing one envelope | 130.8 | 7.6 M |
| reserve/commit, 4 threads | 237.0 | 4.2 M |
| reserve/commit, 8 threads | 270.5 | 3.7 M |

Reading:

- An uncontended admission is ~8 ns — a handful of atomic adds plus the tree
  walk to the funding lane. This is the floor every request pays; it is far
  below any I/O or consensus cost, so admission is not the bottleneck.
- A per-session child budget (created when a tenant/node envelope is threaded)
  costs ~27 ns including the child's own counter allocation.
- Concurrent workers charging **the same** envelope contend on its atomic
  counters: ~131 ns/op at 2 threads, flattening toward ~270 ns/op by 8. This is
  the deliberate cost of a shared, lock-free envelope (doc 10) — real but
  bounded, and per independent session/tenant each envelope is separate, so
  cross-session work does not contend here.

Method: each case warms up for iters/10, then times `iters` iterations with
`std::time::Instant`; `std::hint::black_box` prevents the reserve/commit from
being optimized away. Numbers vary a few percent run to run; the table is one
representative 5 M-iteration run.

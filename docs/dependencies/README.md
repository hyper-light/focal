# Dependency review

The [inventory](inventory.tsv) records all 286 external packages from `cargo metadata --format-version 1 --locked --offline` on 2026-10-05, including build, development, and target-conditional dependencies. Every package declares license metadata. `Cargo.lock` is the reproducibility authority; refresh this inventory when dependencies change.

The full `cargo-deny` 0.20.2 check passed on 2026-09-05 against the fetched RustSec database and [repository policy](../../deny.toml), targeting arm64 macOS and x86-64 Linux: zero advisory, ban, license, or source errors. Ten duplicate-version warnings remain. No advisories are suppressed. Repeat with `cargo deny check advisories bans licenses sources`; this remains a blocking CI gate.

Since 2026-09-29 the one cryptographic provider is `aws-lc-rs` 1.18.1 over `aws-lc-sys` 0.45.0 (AWS-LC 5.7.0), behind `rustls`, `quinn`, `quinn-proto`, `rcgen` and `x509-parser` and for the ECDSA verification of enrollment statements; `ring` is enabled by no focal crate and no feature ([07](../archictecutre/07-decisions-and-traceability.md) F57, enforced by `scripts/check-contracts.py`). Both provider crates are built from the sources under [`vendor/`](../../vendor/README.md), verbatim copies of the crates.io archives whose SHA-256 that file records, so a release is built from reviewed sources and without the registry; the notices and the SBOM list them from `Cargo.lock` with that archive as their locator. The change added eight external packages to the inventory (`aws-lc-rs`, `aws-lc-sys`, `cmake`, `dunce`, `fs_extra`, `jobserver`, `pkg-config`, `untrusted` 0.7.1) and removed none: `ring` 0.17.14 stays in the lockfile only as `quinn-proto`'s dependency for `wasm32-unknown-unknown`, a target focal does not build, and is compiled into no focal executable (`cargo tree -i ring` is empty on every shipped target). `cargo deny check advisories bans licenses sources` passed on 2026-09-29 with seven duplicate-version warnings (`bitflags`, `getrandom`, `heck`, `linux-raw-sys`, `rustix`, `syn`, `untrusted`) and no advisory suppressions; the provider's licenses (`ISC AND (Apache-2.0 OR ISC) AND Apache-2.0 AND MIT AND BSD-3-Clause AND (Apache-2.0 OR ISC OR MIT) AND (Apache-2.0 OR ISC OR MIT-0)`) resolve within the allowed set. The provider's CPU jitter entropy source is on; what it costs a process at its first randomness, and the upstream change that halves it, are recorded in [09](../archictecutre/09-implementation-status.md).

Since 2026-10-03 the shipped binaries hold neither `raft` nor `raft-proto`: the consensus core is hyper-raft, vendored from the shared repository (`vendor/hyper-raft/SNAPSHOT`, with `vendor/hyper-timing`), and focal's WAL and wire keep raft-rs's protocol-buffer encoding through focal's own codec ([27](../archictecutre/27-consensus-roadmap-and-slates-port.md) §14). `raft-proto` is a test dependency, the oracle that codec is held to byte for byte, pinned to one explicitly reviewed upstream PR revision; no protocol-buffer runtime ships. hyper-raft brings `crc32c` (its own records' checksum). Since F-1 and D-2 began (27 §15), the durable shell is vendored from the same revision with what it builds on (`vendor/hyper-durable`, `hyper-log`, `hyper-block`, `hyper-liveness`): they bring no crate the tree did not already hold (`rustix` and `windows-sys` for the block layer's platform calls, `getrandom`). See [exact provenance, tradeoffs, and test evidence](raft-upstream.md) and [the codec boundary](../../crates/focal-consensus/SECURITY.md).

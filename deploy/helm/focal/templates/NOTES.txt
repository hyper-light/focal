Focal {{ .Chart.AppVersion }} in namespace {{ .Release.Namespace }}.

1. Wait for focal-founder-0 to be Ready.
2. Issue one invitation per host pod from the founder and install them as
   the secret "{{ .Values.invitationsSecret }}" (see deploy/kubernetes/invitations.sh):
     kubectl -n {{ .Release.Namespace }} exec focal-founder-0 -c focal -- \
       /focal --data-dir /var/lib/focal invite node --node <pod> --output - > <pod>.invite
     kubectl -n {{ .Release.Namespace }} create secret generic {{ .Values.invitationsSecret }} --from-file=<pod>.invite=<pod>.invite ...
3. The host pods enroll at their first start and join the placement.
4. Every pod starts at single-node durability (survive: node, max_failures: 0),
   the only first start a lone node can satisfy. Once every host pod is Ready,
   commit the requested policy ({{ .Values.survive }} survival, max_failures
   {{ .Values.maxFailures }}, mounted as /etc/focal-target/target.yaml) from the founder:
     kubectl -n {{ .Release.Namespace }} exec focal-founder-0 -c focal -- \
       /focal --data-dir /var/lib/focal plan deployment --config /etc/focal-target/target.yaml --output /var/lib/focal/target.plan
     kubectl -n {{ .Release.Namespace }} exec focal-founder-0 -c focal -- \
       /focal --data-dir /var/lib/focal apply deployment --plan-file /var/lib/focal/target.plan
   The committed policy then carries every restart; the configmap never has to follow it.

Probes ask the node (`inspect node --probe alive`); `authoritative` and
`policy` are for inspection, never for restarts. Resource and volume requests
are an unqualified bootstrap allocation (doc 08 §5).
